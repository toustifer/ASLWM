摘要

Dreamer、TD-MPC 与 JEPA 风格的预测器等潜在世界模型，通过在表示空间优化未来控制，实现了高效规划。 但仅凭预测精度并不能保证被规划的动作仍然以有用的方式改变想象出的未来。 我们识别出上下文塌缩（Context Collapse）：随着视觉上下文增强，自回归潜在预测器可以在保持高未来状态相似度的同时，对不同动作序列几乎不再敏感。

ActSWM 基于 LeWM 风格的表示空间预测，但把动作敏感性当作一种几何约束，而非辅助 readout。 与可随编码器协同适配的联合逆动力学目标不同，ActSWM 将 rollout 分离压力与一个固定的逆动力学约束相结合，使替代动作的未来在长时 horizon 下仍然可区分。

在 VPT Minecraft 轨迹上的步漂移诊断、闭环 MineStudio 规划，以及针对 D2E G-IDM 的跨游戏局部动作恢复实验中，ActSWM 保持更大的动作间隙、提升多步任务成功率，并支持从未标注的游戏视频中做可扩展的动作伪标注。

方法

上下文塌缩

先前的潜在规划器（PlaNet、Dreamer、TD-MPC、LeWM）大多优化未来状态的保真度。 更长的上下文或多步 rollout 损失可以降低复合误差，但它们并不会自动保持动作条件生效： 预测器可能从视觉历史外推出状态演进，却对候选控制不再敏感。

这与经典的曝光偏差不同。对规划而言它更深层：如果真实动作与替代动作的 rollout 塌缩到一起，CEM 风格的规划器就无法比较不同动作序列的下游后果。

ActSWM 设计

ActSWM 继承 JEPA / LeWM 的表示空间预测，再加入 rollout 级分离和一个受逆动力学思想（如 WAM）启发的非自适应动作约束，同时避免联合的编码器–readout 协同适配。

论文图 1：ActSWM 概览——从上下文塌缩到动作敏感的潜在 rollout、规划与跨游戏动作恢复。

1. 预测主干

一个 JEPA 风格的潜在预测器（LeWM 谱系）在动作条件的潜在空间中预测未来表示，而非像素。

2. Rollout 分离

一个 hinge 风格的分离损失让真实动作与替代动作的未来在多步 rollout 中保持可区分。

3. 固定 IDM 约束

一个冻结的逆动力学 readout 让动作恢复成为潜在转移上的稳定几何约束，不同于联合训练的 IDM 辅助头。

ActSWM 把动作敏感性变成明确的训练与评估目标，而不仅仅是预测保真度提升的副产品。

实验一：诊断上下文塌缩

基于 VPT 的离线 Minecraft H5 轨迹，我们检验更强的上下文与多步 rollout 目标是否保持动作条件的分离。 关键指标不仅是未来状态相似度，更是真实动作与替代动作 rollout 之间的动作间隙（action gap）——这正是规划器比较候选未来时所需的量。

实验二：闭环规划

我们在 MineStudio 中闭环地使用 CEM 规划，延续 Dreamer 与 TD-MPC 等潜在规划器所用的模型预测控制思路。 问题在于：动作敏感的 rollout 是否能相对 LeWM 基线真正提升任务成功率，尤其是在多步行为而非接近饱和的短技能上。

火把放置接近饱和，而挖石与建柱从更可靠的动作条件 rollout 中获益最明显。

各任务成功率拆分：ActSWM 在每个任务上都领先，在动作序列最关键的场景中差距最大。

结论：更好的动作敏感潜在动力学转化为更可靠的规划，而不仅是更好的内部指标。

实验三：跨游戏局部动作恢复

在 Minecraft 规划之外，我们考察 ActSWM 是否学到对视频理解与伪标注有益的动作可恢复动力学——把 WAM 等模型的逆动力学思想扩展到多步潜在 rollout。 在 CS2、GTA V 与 Apex Legends 的视频窗口上，我们与 LeWM 以及强视频逆动力学基线 D2E G-IDM 进行对比。

ActSWM 在所有三个游戏上取得最大的 CEM-over-random 动作间隙；在 CS2 与 Apex 上整体按键准确率高于 LeWM，并在 CS2（0.389 对 0.363）与尤其 GTA V（0.761 对 0.050）上带来显著的活跃按键准确率提升。Apex 的活跃按键准确率由 LeWM 领先，我们归因于其较短的上下文窗口。

结论：ActSWM 学到的动作可恢复动力学可迁移到 Minecraft 规划之外的跨游戏视频理解，并为未来空间智能体提供可扩展的伪标注。

数据管线

VPT、STEVE-1、MineDojo 与 Voyager 等游戏智能体路线表明大规模游戏监督的价值，但可训练的动作对齐数据仍需要大量系统工程。 对 ActSWM 而言，管线分为两种模式：GTA V 与 Apex Legends 共用"公开视频采集"骨架（发现、下载、场景分割、过滤、导出）；CS2 则使用基于回放驱动的高控制 POV 采集系统。它们共同支撑世界模型训练、逆动力学监督与跨游戏评估，而不把各游戏当作同一种数据源。

游戏 数据源 核心管线 关键逻辑 输出 工程重点
GTA V YouTube / Bilibili + 精选种子 发现 → 下载 → 场景分割 → 黑名单过滤 → 导出 四个轻量检测器拒绝死亡、菜单、加载与静止片段 干净片段 + 清单 + 续跑日志 大规模公开视频清洗与并行可续跑执行
Apex Legends YouTube + 精选种子 发现 → 下载 → 场景分割 → HUD 白名单 → 导出 通过战斗 HUD 模板匹配（带启发式回退）正向确认游戏画面 干净片段 + 清单 + 续跑日志 与 GTA 同骨架，但过滤哲学相反
CS2 竞技回放 demo 解析 Demo → 启动 / Hook → 帧级控制 → 捕捉 POV → 编码 程序化回放控制，带同步的逐玩家、逐回合录制 结构化 POV 视频 + 下游对齐数据 高控制自动捕捉，而非公开视频抓取
GTA V 管线

目标：从公开 GTA V 游戏视频构建大规模干净片段语料，用于 IDM 与世界模型训练。

管线：系统通过关键词搜索与可信种子 URL 发现候选，以受限分辨率下载视频，应用基于 PySceneDetect 的场景分割，并在策略级片段决策前运行四个轻量帧级检测器。

重要性：GTA 是公开视频管线的参照：一种黑名单策略显式枚举死亡画面、菜单/商店视图、加载画面与低运动片段等坏内容，然后仅导出保留的片段，并以清单支持续跑。

Apex Legends 管线

目标：从公开视频中挖掘战斗有效（combat-valid）的 Apex 游戏画面，同时保留短小、快速、高动作的片段。

管线：Apex 复用 GTA 的采集骨架——多语言发现、下载与场景分割——但用主 hud_gameplay 检测器加加载画面拒绝，替换掉黑名单过滤。

重要性：过滤哲学被反转：它不枚举坏帧，而是通过战斗 HUD 线索（对弹药、剩余小队、罗盘与方向标记做模板匹配，模板不足时用启发式回退）正向确认游戏画面。这避免了因快速镜头变化下基于运动的规则失效而误弃真实战斗片段。

CS2 管线

目标：直接从回放 demo 采集可控的第一人称竞技画面，而非抓取不受控的公开视频。

管线：系统解析 CS2 demo，通过 HLAE 风格 hook 启动游戏，经 demo 控制插件下发帧级回放命令，用 Windows Graphics Capture 捕捉各玩家 POV 流，并编码为逐回合的视频输出。

重要性：CS2 本质上是高控制采集栈，而非公开视频清洗线。它产出可复现的逐玩家、逐回合录制，后续可对齐为下游监督与伪标注工作流。

结论：跨游戏数据采集并非单一可复用配方：GTA V 与 Apex 共享采集骨架但在过滤逻辑上迥异，CS2 则需要完全不同的回放驱动采集栈。工程贡献恰恰是这层"游戏感知适配层"，使跨游戏动作监督成为可能。

贡献

1. ActSWM

一个 JEPA 风格的动作敏感世界模型，让长时潜在 rollout 对动作差异保持响应，而非塌缩成动作无关的未来。

2. 规划与恢复

相比 LeWM 更强的 MineStudio 规划、更大的长时动作间隙，以及优于 D2E G-IDM 等视频 IDM 基线的跨游戏恢复。

3. 数据系统支撑

覆盖公开视频清洗与回放驱动样本生成的三条游戏感知管线，支撑可扩展的训练与动作伪标注。
